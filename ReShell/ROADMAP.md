# ReShell: Roadmap

## Суть
Постепенно ускоряем Windows: заменяем свои скрипты на PowerShell/Python (парсинг, обход файлов, логи, системные твики) маленькими бинарниками на Rust.

- **Почему**: запуск `powershell.exe` занимает 300+ мс (и ещё дольше, если `Add-Type` компилирует C# при каждом старте); Rust-exe стартует за миллисекунды и работает в 10–100 раз быстрее на обходе файлов и парсинге.
- **Как**: один скрипт → один exe (или подкоманда общего `reshell.exe`). Поведение и аргументы остаются те же, чтобы замену можно было сделать без переучивания. Старый скрипт лежит рядом до тех пор, пока замена не прошла проверку.
- **Где живёт**: плагин для `plugin-launcher` (вшивается в `payload/`, ставится и откатывается его кнопками), как rust-search и rtaskmgr-win32.
- **Правило**: каждую замену меряем. Нет замера «до/после» — нет галочки.

## Фаза 0. Основа
1. Cargo-проект `ReShell/` (статический CRT, `opt-level=3`, `lto`, `panic=abort`, как у остальных плагинов). Один бинарник `reshell.exe` с подкомандами: `reshell <команда> [аргументы]`.
2. Общий модуль: Win32 через крейт `windows` (без `Add-Type`), логирование в `%LOCALAPPDATA%\reshell\log.txt`, сохранение прежнего состояния перед любым изменением системы (для отката).
3. Замер: `scripts/bench.ps1` гоняет `hyperfine` (или 20 прогонов `Measure-Command`) по старому скрипту и новому exe, пишет таблицу в `BENCH.md`.
4. Запись в `plugin-launcher`: карточка «ReShell», install/uninstall, добавление в `payload.txt`.

## Фаза 1. Первые замены (уже есть готовые скрипты)
1. **`SuperSaver.ps1` → `reshell saver on|off`**: план питания, частота экрана (`EnumDisplaySettings`/`ChangeDisplaySettings`), яркость (WMI). Прежняя частота сохраняется в `%LOCALAPPDATA%\reshell\`, а не в `%TEMP%`. Сейчас скрипт при каждом запуске компилирует C# через `Add-Type`, это самый явный выигрыш.
2. **`desktop-hotkeys.ps1` → `reshell hotkeys`** (фоновый процесс): Win+1/2/3 → рабочий стол, Win+` → предыдущий. Хук клавиатуры (`SetWindowsHookEx`) на Rust вместо PowerShell, который висит в памяти (~60–100 МБ) ради одного хука. Модуль `VirtualDesktop` заменить на прямой COM `IVirtualDesktopManagerInternal` (недокументирован, меняется между сборками Windows: держать таблицу GUID по номеру сборки и падать в понятную ошибку, а не крашить explorer).
3. Замер обоих, запись в `BENCH.md`, старые `.ps1` удаляются только после недели ежедневного использования без проблем.

## Фаза 2. Частые утилиты (обход файлов, парсинг, логи)
Каждый пункт — отдельная подкоманда, по мере надобности, не всё сразу:
1. **`reshell clean`**: чистка `%TEMP%`, кэшей браузеров, `SoftwareDistribution\Download`, дампов; сначала показывает, что и сколько удалит (как удаление в rust-search: скан → подтверждение → действие), в корзину по умолчанию.
2. **`reshell du <путь>`**: размер папок через чтение MFT (код уже есть в rust-search, переиспользовать, а не писать заново).
3. **`reshell log <файл|канал>`**: фильтр и хвост логов, включая журнал событий Windows (`EvtQuery`) вместо медленного `Get-WinEvent`.
4. **`reshell startup`**: список и отключение автозагрузки (Run-ключи, папка Startup, планировщик, службы) с сохранением прежнего состояния.
5. Источник новых пунктов: любой свой `.ps1`/`.py`, который запускается чаще раза в день или работает дольше секунды.

## Фаза 3. Ускорение самой системы (обратимые твики)
Только то, что можно откатить; каждое изменение записывается в журнал отката до применения:
1. **`reshell tweak`**: набор проверенных настроек (отключить телеметрию-службы, фоновые приложения, анимации, Game DVR и т.п.) с режимами `list` / `apply <имя>` / `revert <имя>` / `status`.
2. Каждый твик — запись в таблице: что меняет (ключ реестра/служба), прежнее значение, как проверить эффект. Без «магических» твиков, эффект которых нельзя измерить.
3. Замер эффекта: время загрузки (`Microsoft-Windows-Diagnostics-Performance`), RAM после загрузки, число процессов. До/после в `BENCH.md`.
4. Интеграция с кнопкой «Откатить всё» в `plugin-launcher`.

## Фаза 4. Заменить фоновые процессы Windows
Как rtaskmgr и rust-search, но для других тяжёлых штук, каждая отдельным решением:
- кандидаты: Widgets, фоновый OneDrive, ненужные службы Xbox/Edge update; замена — отключение + лёгкий Rust-аналог, если функция нужна.
- критерий входа: процесс заметен в RAM/CPU на чистой системе, и его отключение обратимо.

## Дальше
- `reshell` как замена `powershell -c` в ярлыках и планировщике (запуск без окна консоли, subsystem windows для фоновых команд).
- Тихий режим и вызов из `plugin-launcher install reshell --yes`.
- Проверка на чистой Windows 11 в виртуалке (общий пункт 1 роадмапа лаунчера).

## Ограничения
- Системные твики требуют прав администратора; хоткеи и `saver` — нет (кроме смены плана питания у некоторых политик).
- COM виртуальных рабочих столов недокументирован и ломается при обновлениях Windows.
- Скрипты, которые в основном ждут сеть или внешнюю программу, переписывать бессмысленно: выигрыш только на старте.

## Статус
- **Фаза 0** (частично): Cargo-проект `ReShell/` собирается (330 КБ), подкоманды в `src/`. Не сделано: общий модуль логов, `bench.ps1`, карточка в plugin-launcher.
- **Фаза 1.1** `reshell saver on|off`: написано, юнит-тест на разбор GUID проходит. **На живой системе не запускалось** (kill лаунчеров, смена плана питания и частоты экрана). Замер старта: `reshell` ~19 мс против ~340 мс у `powershell -NoProfile` + `Add-Type` (15 прогонов, 2026-11-15); это старт, не вся работа скрипта (`powercfg` вызывается как внешний процесс).
- Отличия от `SuperSaver.ps1`: яркость задаётся в плане питания (powercfg), а не через WMI; `off` больше не выставляет яркость 70, а просто возвращает план «Сбалансированная»; прежняя частота хранится в `%LOCALAPPDATA%\reshell\saver_hz.txt`, а не в `%TEMP%`.
- **Фаза 1.2** `reshell hotkeys`: написано, собирается, тест разбора реестра проходит; **на живой системе не запускалось**. Отличие от плана: без COM `IVirtualDesktopManagerInternal`. Текущий стол и их число берутся из реестра (`...\Explorer\VirtualDesktops`), переключение шлёт Ctrl+Win+←/→ нужное число раз (Win пользователь уже держит). Плюс: не ломается между сборками Windows. Минус: идёт через анимацию переключения, нужны включённые системные сочетания. Перед проверкой остановить старый `desktop-hotkeys.ps1`, иначе два хука сработают дважды.
- **Вшит в plugin-launcher** (2026-11-15): payload\reshell.exe; установка topbar кладёт eshell.exe в Program Files\topbar, пишет HKCU\...\Run\reshell и запускает его; удаление topbar убирает всё. Без аргументов eshell = hotkeys. Установка из лаунчера не проверялась.
